# 魔兽争霸 III 崩溃分析工具 (War3CrashAnalyzer) - 开发文档

本工具是一个专为魔兽争霸 III (War3) 地图玩家与开发者设计的崩溃诊断环境，通过崩溃日志分析、静态审计和泄露定位，帮助定位地图崩溃、内存泄露与资源引用问题，并把诊断结果转交给地图作者。

## 🏗 项目架构

项目采用模块化设计，将界面 (GUI)、业务逻辑 (Core) 与底层引擎 (Engine) 彻底解耦，方便后续功能扩展与 AI Agent 维护。

## 🛠 核心组件功能

### 1. 静态审计 (Core.Auditor)
*   **强力提取**：利用常用字典从 MPQ/W3X 中提取核心脚本与配置文件。
*   **资源审计**：扫描模型路径与贴图引用，并在已执行强力提取的情况下比对缺失文件。
*   **崩溃日志分析**：读取 `Errors/*.txt` 与 `.dmp`。先解析日志明文原因（内存不足、文件损坏、打开/加载失败），编辑器崩溃不再套用 Storm.dll 偏移；再解析完整 `Stack Trace (Manual)`，崩溃指令地址无效（如空函数指针调用）时自动回退到栈内首个有效模块帧；同时从栈帧与 `Loaded Modules` 识别对战平台（`azurewrath.dll`、`kk*`）、YDWE 运行时（`yd_*`）、JassDebug 插件、显卡驱动与输入法；最终统一输出四行结论：**一句话结论 + 责任归属 + 建议 + 置信度**。游戏崩溃按 `War3Build` / dmp 模块版本锁定版本，用模块内 RVA 精确匹配 `knowledge.json`。
*   **Dump 解析**：用 `skelsec/minidump` 读取模块表、异常流与异常线程上下文，从模块的 `VS_FIXEDFILEINFO` 自动识别游戏版本（如 `1.27.0.52240 → 1.27a`），并用 EBP/RBP 链回溯完整调用栈；异常地址不在任何模块内时改用栈顶有效帧定位。日志里没有版本号时也能靠 dmp 完成版本锁定与栈指纹计算。
*   **栈指纹聚类**：用「游戏版本 + 栈顶 5 个非系统帧」计算 12 位指纹，写入本地 `history.db`，并按日志去重统计同一崩溃的累计次数与涉及地图数；批量诊断结束时会列出重复崩溃排行，便于判断是普遍问题还是个别地图问题。
*   **三步诊断**：「崩溃诊断」页面向玩家只保留三个步骤——①确认魔兽目录；②选择日志并诊断（默认 Errors 最新一份，可在下拉框切换或浏览其他日志）；③诊断成功后出现唯一按钮「⬆ 上传服务器」，提示上传有助于采集错误样本、构建大数据平台，让故障定位更精准。启动时不再自动批量诊断，诊断日志窗口保持简洁。
*   **崩溃历史（作者工具）**：在「地图作者工具」页点击「📊 崩溃历史」，按累计次数查看本机指纹聚类，可筛选指纹/版本/模块内偏移/归属/日志名，并勾选只看重复（≥2 次）；选中指纹可查看调用栈、对应知识库结论与全部样本日志；「诊断日志」页签可回看每份日志的完整诊断文本。数据只读取本机 `history.db`，不联网。
*   **自动收集**：后台监听配置目录、同级魔兽副本以及运行中游戏进程所在目录的 `Errors`，只对启动后出现的新日志自动诊断并弹出托盘提示；可在「高级工具 & 设置」中关闭。诊断只在本机进行，不会因此额外上传日志。
*   **诊断包导出（作者工具）**：在「地图作者工具」页一键把最新崩溃日志、同名 `.dmp`、诊断 JSON 与一段摘要文本打包成 zip。JSON 含归一化与原始版本号、地图名与 MD5、插件列表、栈指纹、调用栈和四行结论；摘要使用 UTF-8 BOM 并自动复制到剪贴板，可直接粘贴给作者。包内不含本机绝对路径。
*   **一键上传（第 3 步）**：在「崩溃诊断」页诊断完成后点击「⬆ 上传服务器」，上传对话框会锁定刚诊断的那份日志并自动匹配同名 dmp，可附加 KK 最近一次会话日志；上传前展示清单与隐私说明，确认后调用 `/api/upload`，成功回显并复制 6 位上传码。不会读取地图文件，超过 50 MB 或日志命名不被服务端识别时直接提示。托盘菜单「上传最近崩溃日志」与「地图作者工具 → 上传日志到服务器」仍可用。
*   **上传码查询（作者工具）**：上传成功后程序会记住上传码；在「地图作者工具」页点击「🔎 查询上传码状态」可再次查看服务端诊断、原始文件保留状态与维护者反馈（待处理 / 复核中 / 已处理 / 需补充材料）。查询只读取脱敏派生信息，不会下载或显示原始日志。
*   **指纹定位（作者工具）**：在「地图作者工具」页点击「指纹定位」，可导入诊断包/诊断 JSON，或输入 12 位指纹从服务端拉取聚合详情。工具按知识库条目与作者标注推导可疑 API（如 `GroupEnum*`、`TimerStart`、`ExecuteFunc`），打开地图脚本列出每个调用的行号与代码片段；同时调用本机 `pjass.exe` 做语法检查。脚本提取优先使用外部 `w2l.exe`（w3x2lni）还原加密地图文件名；对于删除了 `(listfile)` 的加密地图，`w2l` 会拒绝直接转换，工具先用 MPQEditor 把地图展开成目录，再以目录模式交给 w3x2lni，仍可得到真实文件名与完整 listfile。展开后会扫描脚本、物编与模型中的资源路径，用地图自身 MPQ 哈希表校验并补全 `File00000xxx` 占位名，报告中给出资源名识别覆盖率。超大脚本（上千个函数）可能让 pjass 直接崩溃，工具会按顶层函数边界自动分段检查并还原原始行号，报告会标注“分 N 段检查”；分段仍失败时明确提示“语法检查未完成”，不会误报为 0 个错误。诊断包导入、脚本分析与语法检查全部在本机完成。

### 2. 内存监控 (Engine.Memory)
*   **JassVMMonitor**：通过读取 `Game.dll` 内存，追踪 JASS 虚拟机的活跃线程、调用栈偏移量。
*   **AgentMonitor**：实时监控引擎对象（单位、点、组、计时器等）的句柄计数与内存占用。
*   **句柄快照**：对比不同时间点的句柄状态，精准定位内存泄露源。

### 3. 泄露定位&修复 (Core.Fixer)
*   手动发起扫描：选择地图或脚本后只在本地生成候选清单，不会自动改写文件。A 级（可安全自动修复）默认勾选，B 级只生成补丁，C 级仅报告。
*   自动修复只覆盖三类 A 级模式：局部 `location`、局部 `group`、函数内新建的 `force`（`CreateForce`），以及同一语句中可安全提升的内联点/组。`CreateTrigger` / `CreateTimer` / `InitHashtable`、共享/全局句柄、GUI 变量与逃逸句柄不会自动销毁。
*   应用前展示逐条 diff；写入目标是 `<地图名>_leakfixed.w3x` 副本，原图保持只读，可一键撤销。写回前做 pjass 语法检查与 `local` 声明位置检查，写回后重新提取脚本校验，失败自动回滚。
*   报告可导出 Markdown / JSON / CSV，包含规则、等级、置信度、证据片段、覆盖范围与修复状态；崩溃诊断确认“内存不足”时，诊断页会追加只读的疑似泄露证据。

### 4. 配套 Web 服务 (Server)
*   **自动上报与聚合**：服务端提供 `/api/report`、`/api/stats`、`/api/aggregates`，按「地图身份 + 栈指纹」聚合相同崩溃并统计次数；`/author` 供地图作者按地图哈希或地图名查询崩溃指纹排行、趋势与脱敏样本。路由按职责拆分在 `server/blueprints/`，入口仍是 `server/app.py`。
*   **作者标注**：作者可回填根因、来源与置信度，写入需服务端配置 `WAR3_ANNOTATION_TOKEN`（未配置时禁用），标注同步沉淀到案例缓存，不自动改写全局 `knowledge.json`。
*   **案例复核与合并**：`/admin/cases` 需配置 `WAR3_ADMIN_TOKEN`，可按地图、指纹、模块、版本、来源与合并状态筛选案例；支持导出知识库片段、试运行和批量合并。合并时版本与偏移自动归一，同地址默认跳过，勾选覆盖才更新且保留原有归属/建议/API 线索；写入前自动备份 `knowledge.json`，原子替换并热更新服务端缓存，操作写入审计。
*   **原始日志采集**：`/upload` 提供崩溃记录与 KK 平台日志两个上传区，支持拖拽文件夹与 zip；单次上限 **50 MB**，按内容哈希去重，成功后返回 **6 位上传码**。崩溃区按子目录识别多次崩溃，KK 区从 `war3dll.log` 补充版本、地图名与 MD5，覆盖平台局没有 `Errors` 文件的情况。
*   **服务端入库**：上传的每份崩溃日志会在服务端复用客户端解析模块重新诊断，写入 `crash_reports` 并累加 `crash_aggregates`，与自动上报共用同一套知识库与聚合口径；重复内容只补齐字段，不重复计数。
*   **维护者管理端**：`/admin/uploads` 需在服务端配置 `WAR3_ADMIN_TOKEN`，请求头携带 `X-Admin-Token`。可按上传码、地图、版本、归属、指纹与反馈状态筛选；查看诊断结论与调用栈、在线预览文本、单文件下载、整包 zip 下载，以及在线删除原始文件（诊断元数据保留）。预览、下载、删除、补跑入库与反馈写入均写入 `admin_audit` 审计（含 IP 哈希）。
*   **上传反馈状态**：维护者可在上传详情中把复核进度标为待处理 / 复核中 / 已处理 / 需补充材料，并附最多 500 字备注；状态与备注随 `/api/upload/<code>` 和 `/u/<code>` 公开给提交者，客户端「上传码查询」同步展示。
*   **客户端下载入口**：`/download` 展示当前版本、网盘链接、提取码与更新说明；维护者在 `/admin/download` 用 `WAR3_ADMIN_TOKEN` 随时更新，保存即生效，无需重启服务；链接留空可下线入口。公开接口 `/api/download` 只返回配置字段，不涉及上传数据。
*   **保留与访问**：原始文件存放在服务端私有目录 `server/uploads/`，默认保留 **14 天**（可配 7~15 天）后自动删除；`/u/<code>` 与 `/api/upload/<code>` 只展示版本、地图、偏移、诊断摘要与保留状态，不公开原始日志或本机路径。
*   启动方式、接口字段、环境变量与反向代理注意事项见 `server/README_SERVER.md`（服务端依赖 `flask`，与客户端依赖分开安装）。

### 5. 高级工具 (JassDebug)
*   **弹窗解析**：JassDebug.asi 在本地客户端发生未处理异常时弹出标题为「调试输出」的窗口，内容包含当前 JASS 语句地址、语句内容、所属函数、逐级上级函数链，以及 JASS 代码起始地址与偏移。在「高级工具 & 设置」点击「解析弹窗」，软件会只读抓取该窗口文字（`EnumWindows` + `WM_GETTEXT`，不注入进程），也支持从剪贴板粘贴截图文字或手抄内容，解析后输出与主诊断一致的四行结论并列出调用链；结果可一键复制。仅限本地客户端调试，严禁在联网对战平台使用。

## 🚀 开发者指南 (AI Agent 更新须知)

如果您需要为本项目添加新功能，请遵循以下约定：

1.  **添加新功能标签页**：
    *   在 `gui/tabs/` 目录下新建一个类，继承自 `BaseTab`。
    *   在 `gui/app.py` 的 `setup_ui` 方法中实例化并添加到 `notebook`。
2.  **更新崩溃知识库**：
    *   直接修改 `knowledge.json`，按 `modules -> 模块名 -> 版本 -> RVA` 增加条目；所有条目必须声明 `source / confidence / verified`。
    *   可选字段 `apis` 用于作者定位：填写该崩溃可能相关的 JASS API 名称（如 `GroupEnumUnitsInRange`），指纹定位会据此列出脚本调用位置。
3.  **底层 API 扩展**：
    *   如果需要新的 Windows API 或内存读取逻辑，请在 `engine/memory.py` 中封装，不要直接写在 GUI 类里。
4.  **日志输出**：
    *   在 UI 类中调用 `self.log("消息")`，该消息会同步显示在界面的诊断日志区域。
5.  **数据目录**：
    *   只读资源用 `base_dir`，历史库、报告、临时文件一律用 `data_dir`（打包后位于 exe 同级，`_MEIPASS` 退出即删）。

## 📦 依赖项

项目依赖以下第三方库，可执行 `pip install -r requirements.txt` 安装：
*   `psutil`: 进程与内存监控
*   `mpyq`: MPQ 地图包解析
*   `pillow`: 图像处理 (用于 UI 图标与系统托盘)
*   `pystray`: 系统托盘图标支持

### 外部程序（可选，不随项目分发）

*   `pjass.exe`：JASS 语法检查器（BSD-2-Clause）。放在 `tools/pjass.exe`、程序根目录，或设置环境变量 `WAR3_PJASS`；也可在定位对话框中手动选择。默认使用 `+nosemanticerror`，不需要 `common.j` / `Blizzard.j`。超大脚本触发 pjass 崩溃时会自动分段重试。

## 🔐 数据与隐私

*   自动上报由「高级工具 & 设置」中的开关控制，默认关闭，开启后按设定间隔上报。
*   上报内容为崩溃日志原文（可能包含 Windows 用户名、计算机名、本地文件路径）、地图名与哈希、游戏版本、模块内偏移、调用栈、栈指纹、归属结论与分析结果；不会上传地图文件或原始 dmp 文件。
*   网页手动上传为可选兜底：可上传崩溃日志、dmp 与 KK 平台日志（单次 50 MB），生成 6 位上传码；原始文件存放在服务端私有目录，默认 14 天后自动删除。上传码状态页只展示版本、地图、崩溃位置、诊断摘要与维护者反馈，不公开原始日志、Windows 用户名、计算机名或本地路径。KK 安装路径因用户而异，页面仅以默认目录举例，用户需从快捷方式打开实际安装位置后进入 `log`。

## ⚠️ 安全警告

本地调试只读取游戏进程内存；JassDebug 插件（ASI）会挂接游戏进程。**严禁在任何联网对战平台（如 KK、网易、官方战网）使用插件或内存监控功能**，否则有封号风险。静态审计、资源提取与泄露定位/修复不接触游戏进程，可安全使用。
