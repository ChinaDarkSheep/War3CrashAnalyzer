# 泄露修复规则目录（P5.3）

日期：2026-11-06
实现：`core/leak_catalog.py`、`tests/test_leak_catalog.py`

## 1. 目的

把“创建函数 -> 句柄类型 -> 销毁函数 -> 风险等级”从 `constants.py` 和
`fixer.py` 中独立出来，形成一份可审计、可测试的规则目录。规则层只消费
P5.2 的 `CreationSite` 事实，不做源码匹配，也不直接改写脚本。

原则仍然是：**宁可少修，不可错修**。A 级规则只有在逃逸、共享、长期持有、
循环、多出口、无法解析等检查全部通过后才会进入自动修复。

## 2. 分级

| 级别 | 含义 | 允许的写盘行为 |
| --- | --- | --- |
| A | 可以自动修复 | 生成编辑并写入修复版地图 |
| B | 只生成补丁建议 | 展示 diff，由作者确认 |
| C | 只报告 | 解释原因，禁止自动销毁 |

## 3. 规则总表

| 规则 | 名称 | 类型 | 级别 | 修复方式 | 置信度 |
| --- | --- | --- | --- | --- | ---: |
| L01 | 局部点与内联点 | location | A | auto | 0.95 |
| L02 | 局部单位组 | group | A | auto | 0.90 |
| L03 | 新建玩家组 | force | A | auto | 0.90 |
| L04 | 矩形与区域 | rect | B | patch | 0.80 |
| L05 | 特效与闪电 | effect / lightning | B | patch | 0.75 |
| L06 | 内联单位组与玩家组 | group / force | B | patch | 0.70 |
| L07 | boolexpr 条件与过滤器 | boolexpr | B | patch | 0.70 |
| L08 | GUI 单位组 | group | B | report | 0.90 |
| L09 | 销毁后未置空 agent 变量 | 全部已纳管 agent | A（辅助） | auto（仅置空） | 0.85 |
| L10 | 共享句柄与长期对象 | 全部已纳管类型 | C | report | 0.99 |

### L01 局部点与内联点

- 证据：`函数 第 N 行的 location 由 GetUnitLoc 创建，函数出口前未调用 RemoveLocation。`
- 适用：局部变量，或可直接提升的内联创建。
- 不适用：写入全局/数组/哈希表、传给未知函数、提前返回、循环内绑定的局部变量、
  无法解析语句、销毁前置空、仅部分路径销毁、共享/长期对象。

### L02 局部单位组

- 证据：单位组由 `CreateGroup` / `GetUnits*` 等创建，出口前未调用 `DestroyGroup`。
- 不适用：GUI `bj_wantDestroyGroup` 管理的单位组、共享对象、分支内只销毁一次。

### L03 新建玩家组

- A 级白名单仅包含 `CreateForce`、`GetPlayersMatching`、`GetPlayersInIsntance`。
- `GetPlayersAll` 是引擎共享 force，永不进入 L03，统一归 L10。
- 不适用：句柄被返回、存入容器或传给未知函数。

### L04 矩形与区域

- 本版只生成补丁建议，不自动写盘。
- 不适用：`RegionAddRect` 已接管所有权；全局矩形初始化。

### L05 特效与闪电

- 类型目录新增 `effect`（`AddSpecialEffect*` / `AddSpellEffect*`）与
  `lightning`（`AddLightning*`），销毁函数分别为 `DestroyEffect`、
  `DestroyLightning`。
- 只生成补丁建议。贴图特效常被设计为长期存在，必须由作者确认生命周期。

### L06 内联单位组与玩家组

- 内联创建没有变量承接，无法在函数出口统一清理；本版只生成补丁建议。
- 内联位置仍由 L01 自动处理，因为修复器可以在每次使用后立即 `set` + 销毁。

### L07 boolexpr

- `Condition` / `Filter` 的返回值未销毁时只生成建议。
- 不适用：已通过 `TriggerAddCondition` 注册为长期对象（归 L10）。

### L08 GUI 单位组

- 仅解释 `bj_wantDestroyGroup = true` + `ForGroupBJ` 已负责销毁，不产生编辑。
- 这是 B 级中唯一不生成补丁的规则，避免重复销毁。

### L09 销毁后未置空

- 仅当局部 agent 变量已完整销毁、销毁后未再次使用且没有置空时给出。
- 它不作为独立发现，只作为 L01/L02/L03 修复的附加编辑。

### L10 共享句柄与长期对象

- 覆盖 `GetPlayersAll` 共享 force、已注册的计时器/触发器、已挂到触发器条件的
  boolexpr，以及未注册但属于 `timer` / `trigger` / `hashtable` 的对象。
- 只报告并解释原因，自动修复恒为 0。

## 4. 判定顺序

1. 共享或长期对象 -> L10（C，只报告）；
2. 全局变量持有 -> 不列为泄露（全局生命周期）；
3. GUI 管理 -> L08（B，只解释）；
4. 内联 location -> L01；内联 group/force -> L06；
5. 其余按类型进入 L01–L07；
6. 状态为 escaped 时不给 leak 发现，只对全局/数组/哈希表/未知参数给出提示；
7. 状态为 cleaned 时检查是否缺少 `set x = null`，给出 L09 辅助建议；
8. 状态为 leaked 时按规则级别输出 finding，A 级候选再经过 P5.2 自动修复护栏。

## 5. 类型目录

| 类型 | 创建函数来源 | 销毁函数 | 规则 |
| --- | --- | --- | --- |
| location | `LOC_FUNCS` | `RemoveLocation` | L01 |
| group | `GROUP_FUNCS` | `DestroyGroup` | L02 / L06 / L08 |
| force | `CreateForce`、`GetPlayersMatching`、`GetPlayersInIsntance` | `DestroyForce` | L03 / L06 / L10 |
| rect | `RECT_FUNCS` | `RemoveRect` | L04 |
| effect | `AddSpecialEffect*`、`AddSpellEffect*` | `DestroyEffect` | L05 |
| lightning | `AddLightning*` | `DestroyLightning` | L05 |
| boolexpr | `Condition`、`Filter` | `DestroyBoolExpr` | L07 / L10 |
| timer | `CreateTimer` | `DestroyTimer` | L10 |
| trigger | `CreateTrigger` | `DestroyTrigger` | L10 |
| hashtable | `InitHashtable` | `FlushParentHashtable` | L10 |

## 6. 覆盖范围声明

- 自动修复（A）：L01 局部点与内联点、L02 局部单位组、L03 新建玩家组；
  L09 只追加 `set null`。
- 补丁建议（B）：L04 矩形/区域、L05 特效/闪电、L06 内联单位组/玩家组、
  L07 boolexpr；L08 GUI 单位组只解释不写盘。
- 只报告（C）：L10 共享句柄与长期计时器/触发器/哈希表。
- 已纳入类型目录：location、group、force、rect、effect、lightning、
  boolexpr、timer、trigger、hashtable。
- 不处理：单位、物品、可破坏物、region、音效、对话框等未纳管句柄；
  Lua 脚本不支持写入。
- 全局变量持有的普通句柄不视为泄露，也不会自动销毁。

## 7. 评估结果（2026-11-06）

- 18 个用例全部按预期归类；A 级发现 7 个，与预期完全匹配，
  **A 级 precision 100%（7/7）**。
- A 级 recall 7/8（87.5%）：`07_escape_global_location` 按 P5.2 语义属于
  全局逃逸，不应计为泄露，因此只给提示，不产生 A 级发现；
  `16_local_rect_scope` 属于 B 级矩形规则，不参与 A 级召回。
- 共享 force 用例 `08_shared_force` 的两个句柄均为 L10、`fix_mode=report`，
  **自动修复数 0**。
- 单元测试：`tests/test_leak_catalog.py` 19 例；全量回归 116 个测试符合预期。

## 8. P5.4 接口

- `classify_semantics(semantics)`：返回每个创建点的 `CatalogMatch`。
- `leak_findings(matches)`：只取 A/B 级泄露发现。
- `auto_fix_matches(matches)`：只取可自动修复的 A 级候选。
- `coverage_statement()`：生成报告中的覆盖范围声明。
- `rule_for_creator(creator)` / `rules_for_type(type)`：供编辑器选择规则。

修复器 `core/leak_fixer.py` 只消费上述结果，并额外套一层护栏：

- `auto_fixable`（A 级）生成自动编辑；`fix_mode=patch` 生成待预览补丁；`report/none` 只输出提示。
- 已有销毁/置空、部分路径清理、循环内创建或重赋值、函数内无法解析、变量多处赋值，任一命中都不自动改源码。
- 多出口函数降级为补丁，并在每个 return 与函数尾部插入清理。
- `L09` 只在“已完整销毁且未置空”时追加 `set var = null`，不改动销毁语句。

## 9. P5.5 界面与报告接口（2026-11-07）

- 「泄露定位&修复」页只消费 `build_fix_plan()` 与 `build_leak_report()`，自身不重新实现规则判断。
- 默认只勾选 `level == "A" and auto` 的行；`patch` 行需手动勾选，且只导出补丁、不自动写地图。
- 报告统一由 `core/leak_report.py` 生成 Markdown / JSON / CSV：
  - 行字段：规则、级别、置信度、函数、行号、类型、变量、证据、建议、可自动修复、可生成补丁。
  - 全局变量句柄只计入 `summary.global_skipped`，不进入可修复行。
  - Markdown 附可疑函数完整片段和覆盖范围声明。
- 崩溃诊断页只调用 `leak_suspected_from_diagnosis()` 判断是否追加只读证据，不提供改图入口；证据文案由 `crash_evidence_text()` 统一生成。

## 10. P5.6 写回护栏补充（2026-11-07）

- `validate_fixed_text()` 在 pjass 语法检查之外，额外检查函数体内 `local` 是否位于语句之后；违反即判定失败并拒绝写回。
- 同一函数内多条内联创建提升出的 `local` 声明统一排在函数首条语句前；同一文本偏移的插入用优先级保证声明先行。
- 10 张真实地图回归中，pjass 语法、`local` 位置、重新提取校验与完整语义对比均为 0 新增错误。
